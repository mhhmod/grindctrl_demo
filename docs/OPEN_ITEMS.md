# Inputs to confirm with the owner

The repo is runnable and includes its current website assets. These decisions and materials are still needed before a developer can treat a redesign brief as final:

1. **Homepage boundaries:** which homepage sections should change, and which existing parts must stay unchanged. The page scope is confirmed as the homepage (`/`) only.
2. **Priority interactions:** which reference patterns in [the demo brief](DEMO_BRIEF.md) the owner actually wants, and the desired animation level.
3. **Product visuals:** existing synthetic demo UI crops and three conceptual editorial images are supplied for the homepage preview. If a full dashboard screenshot is required, the owner must approve a synthetic concept or provide reviewed captures. Five video briefs are ready in [the creative production pack](CREATIVE_PRODUCTION_PACK.md); the video files have not been produced.
4. **Copy and destinations:** final feature wording, claims, CTA labels and target URLs. The current repo's visible links and sample figures should be reviewed before publication.
5. **Asset approval:** confirmation that the supplied synthetic images and logo may be redistributed in this public developer repository and used in previews.

Do not insert production environment values, credentials, endpoints, real customer data, backend/auth code, database migrations, workflows, deployment configuration, or internal agent settings to fill these gaps. A preview can be built without them.
